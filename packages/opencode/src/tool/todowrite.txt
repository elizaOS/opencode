Create or update the task list for the current coding session. Use it to track non-trivial work and keep progress visible.

Use todowrite when:
- The request has 3+ meaningful steps or multiple files/components.
- The task is complex, risky, or benefits from explicit tracking.
- The user asks for a todo list.
- The user gives multiple tasks or new requirements.
- You discover follow-up work while investigating.

Do not use it for:
- A single straightforward change or command.
- Trivial tasks that take only a few obvious steps.
- Purely conversational or informational answers.

Todo fields:
- content: specific, actionable task text.
- status: pending, in_progress, completed, or cancelled.
- priority: use the available priority values to reflect importance/order.

Rules:
- Capture requirements promptly after receiving or discovering them.
- Break complex work into clear, manageable items.
- Keep exactly one item in_progress when work is active.
- Mark an item in_progress before starting it.
- Mark completed immediately after finishing it, not in large batches.
- Complete the current in_progress item before starting another.
- Cancel items that are no longer needed.
- Update the list when scope changes so it remains accurate.

When unsure on a real coding task, prefer using the todo list. Do not add todos just to perform ceremony on simple work.
